# 빗자루 소동 실시간 서버 교체본

상태: 로컬 검증 완료, 운영 배포 전. 기존 게임의 HTTP 서버는 그대로 유지합니다.

## 바뀌는 구조
- 방 생성, 입장, 시작, 이동, 상태 전달을 한 WebSocket 연결에서 처리합니다.
- 서버는 60Hz로 판정하고, 상태는 약 20Hz로 전송합니다. 게임 중 데이터베이스 읽기·쓰기가 없습니다.
- 클라이언트는 자기 캐릭터의 이동을 즉시 예측하고 서버 결과로 보정합니다.
- 기존 방장 수동 시작, 10초 준비, 90초 대전, 네 명 제한, 방장 승계, 빈 방 정리를 유지합니다.
- 서버는 한 인스턴스로 운영합니다. 재시작하면 임시 방이 정리됩니다.

## 로컬 검증
Node 22.13 이상에서 이 디렉터리에서 `npm ci` 후 `npm test`를 실행합니다. 테스트는 실제 WebSocket 클라이언트 네 개로 입장, 호스트 권한, 준비 시간, 이동, 상태 수신, 방장 승계, 빈 방 삭제를 검증합니다. 지연 수치는 로컬 측정으로, 인터넷 플레이 성능을 보장하지 않습니다.

## 배포 후 전환
Render 계정 연결 뒤 `render.yaml` 설정으로 배포합니다. 무료 인스턴스 설정이며 배포 전 서비스 설정과 계정 한도를 확인합니다. `/health`와 실제 두 클라이언트 접속 검증을 통과한 뒤 GitHub 게임의 `server-config.js`에 반환된 `wss://` 서버 주소를 설정합니다. 그 전에는 빈 문자열을 유지하여 기존 운영 서버를 사용합니다. 확인되지 않은 서버 주소를 추측해서 넣지 마세요.

네트워크 제약이 있는 WebRTC 실험은 운영 코드에 포함하지 않았습니다.
